# ADR 0006: Issuing quotes: frozen snapshots, React-PDF, and a server-only send

Status: accepted (founder, 2026-10-03: only our server can send; revise is in this slice; quotes are numbered when first saved)

## Decisions
1. **A quote is one row; every send is a frozen version.** `quotes` holds the number, the current version and the editable lines. Each send stores `quote_versions.snapshot` (jsonb): everything the document shows, including the business and customer details copied at that moment, the lines with their amounts, the totals, the VAT mode and rate, the wording and number style from the locale pack, the country and currency. The on-screen sent quote and the PDF are drawn **only** from the snapshot. Revising moves a sent quote back to draft with `version + 1` and the same number; earlier versions stay readable.
2. **The number is given when the draft is first saved** (trigger `quotes_assign_number`, same transaction as the save, so a failed save leaves no gap). Deleting a never-sent draft leaves a gap; allowed for quotes, which are not tax documents. Invoices will still be numbered when issued and gapless. Competitors mostly number at creation (Xero, Zoho, QuickBooks); Invoice Ninja offers both.
3. **Sending and revising can only be done by our server.** `send_quote` and `revise_quote` are executable by the `service_role` only. The server reads the draft under the person's own session (row-level security proves it is theirs), works out the totals with the money code, builds the snapshot, and only then calls the function with the secret key (`SUPABASE_SECRET_KEY`, `app/src/lib/supabase/admin.ts`, `server-only`). Nobody can create a sent quote with made-up totals by calling the database directly. The function also refuses a draft that changed after the server read it (`p_expected_updated_at`). The same pattern is for invoices and credit notes.
4. **PDFs are made on the server with React-PDF** (`@react-pdf/renderer`, no headless browser), from the snapshot. Noto Sans (SIL OFL) is embedded as text modules (`app/src/lib/quotes/pdf/fonts/`) so it travels with the code, and covers every South African language written in the Latin alphabet. Characters it cannot draw (emoji, symbols) are dropped from the PDF only; the stored snapshot keeps what was typed.
5. **Sharing happens in the browser.** The send step freezes the quote first, then fetches the PDF and offers it to the phone's share sheet (Web Share API with files), or downloads it where files can't be shared. If the share sheet is closed, the quote is still sent; the sent page can share it again at any time.

## Consequences
- Adding `@react-pdf/renderer` brought 48 packages (supply-chain note: pinned by the lockfile; Dependabot and secret scanning are still to be switched on, see `docs/security-notes.md`).
- Hosting needs `SUPABASE_SECRET_KEY` on the server (Vercel). Without it, sending shows "Sending isn't switched on" and nothing is sent. Steps: `docs/runbooks/server-secret-key.md`.
- `quote_versions` rows are never updated or deleted by the API, and a revision of a sent quote cannot be deleted. When account deletion is built (`docs/security-notes.md`, item 6) it has to respect this.
- Revising sets the quote's status back to `draft` with `version > 1`, shown as "Revising"; the sent versions stay in `quote_versions`. Discarding a revision to go back to the sent version is not built yet (shown as "coming soon" on the revising draft).
- Known and accepted: deleting a login only forgets who sent a version (`sent_by` is set to null; the one change the immutability trigger allows). Deleting an organisation that has sent quotes is refused by the database until an erasure process exists (security notes, item 6); demo-organisation teardown must not rely on cascade.
- If the prefix or counter is changed so a number would repeat one already used, the next free number is taken.

## Addendum: the preview is the real PDF (2026-10-03)
The preview and sent-quote screens draw the server's PDF with pdf.js (`pdfjs-dist`, legacy build for older phones, loaded only on those screens) instead of keeping a second on-screen layout. One document means the preview is exactly what is sent and every future design appears automatically. Cost: a second request and a render of the PDF per preview (about a second), and one more dependency (`pdfjs-dist`; its lockfile entries include an optional native canvas package per platform, not used in the browser). Each version's `snapshot.design` names the design it used (versions sent before designs existed have none and are drawn in the classic design); designs are only ever added, never edited. The preview asks for the PDF with a stamp of the document's content, so it is drawn again whenever anything it says changes. Sent versions are frozen, so caching their PDFs would save re-rendering; not done yet (the route is `private, no-store`).

## Addendum: Classic is refined in place while there are no real customers (2026-10-07)
The rule above stands for released designs once real businesses send real quotes. Until then MakerFlow is on a development project only, so the founder asked for the Classic layout to be improved in place (type scale, spacing, alignment, a footer that now prints). Only layout and spacing changed; no content or numbers did. Because a sent version's PDF is drawn from its snapshot on every request, an already-sent quote on dev now draws with the new layout. From the first real customer, a change to the look of a released design becomes a new design key instead. Needs the founder's review, as this relaxes an accepted decision.
